# Экономия токенов

ClaudeTG уменьшает расход двумя способами: сокращает контекст, который попадает в модель, и ограничивает объём работы, который модель генерирует сама.

## Output tokens

По умолчанию в `.env.example` указан:

```dotenv
CLAUDE_CODE_EFFORT_LEVEL=medium
```

Effort влияет не только на видимый текст, но и на thinking, tool calls и служебные ответы модели. `medium` выбран как компромисс для обычной разработки: он дешевле стандартного высокого уровня, но обычно надёжнее `low` на задачах с несколькими шагами.

Допустимые значения:

- `low` — короткие механические задачи с заранее известным местом изменения;
- `medium` — рекомендуемый режим для повседневной работы;
- `high` — сложная отладка, архитектурные изменения и чувствительные к качеству задачи;
- `xhigh` и `max` — самые дорогие режимы; использовать только когда дополнительное рассуждение действительно оправдано и поддерживается моделью.

После изменения `.env` пересоздайте контейнер:

```bash
docker compose up -d --build
```

### Отключение thinking

```dotenv
CLAUDE_CODE_DISABLE_THINKING=true
```

Это сильнее уменьшает output tokens, но может заметно ухудшить сложное планирование, поиск причин ошибки и многошаговые изменения. Оставляйте `false` по умолчанию и включайте только для простых, хорошо ограниченных задач.

### Prompt suggestions

```dotenv
CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false
```

Подсказки следующего запроса не нужны Telegram-интерфейсу, поэтому они отключены. Это убирает необязательную генерацию после завершения ответа.

### Краткие ответы

Встроенный skill просит Claude не описывать каждый вызов инструмента и не повторять постановку задачи. Итоговый ответ должен содержать результат, изменённые файлы, проверки и оставшиеся риски без полного diff и длинных логов. Это не обрезка готового сообщения: модель изначально генерирует меньше текста, поэтому такие токены не оплачиваются.

## Input tokens

Для входного контекста используются `rg`, `ast-grep`, ограниченные чтения файлов, Repomix с узким `--include` и опциональная Serena. Полный репозиторий автоматически не загружается.

## Что не гарантируется

Нельзя обещать одинаковый процент экономии для каждой задачи. На простой правке разница может быть небольшой. На длинной сессии, большом репозитории или задаче с активным thinking экономия обычно заметнее.

Слишком низкий effort может привести к дополнительным попыткам и в итоге потратить больше токенов. Поэтому сравнивать режимы нужно на повторяемых задачах, учитывая итоговую стоимость и качество, а не только длину одного ответа.

API-side `taskBudget` намеренно не включён по умолчанию. Это beta-возможность, которую кастомный Anthropic-совместимый gateway может не поддерживать. Сначала стоит проверить её на вашем провайдере отдельно, чтобы не ломать рабочие сессии.
