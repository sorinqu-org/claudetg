# Экономия токенов

ClaudeTG уменьшает расход двумя способами: сокращает контекст, который попадает в модель, и ограничивает объём работы, который модель генерирует сама.

## Effort в Telegram

Команда `/effort` меняет effort только для активной Telegram-сессии. Выбор сохраняется в SQLite и применяется к следующему turn, включая сообщения, которые позже запускаются из очереди.

Доступны:

- `auto` — использовать значение модели по умолчанию;
- `low` — короткие механические задачи с заранее известным местом изменения;
- `medium` — рекомендуемый экономный режим для повседневной работы;
- `high` — сложная отладка и чувствительные к качеству изменения;
- `xhigh` — длинные agentic-задачи на моделях, которые его поддерживают;
- `max` — максимум рассуждений без ограничения расходов.

Изменение effort внутри уже начатой длинной сессии может снизить prompt-cache hit rate, поэтому лучше выбрать режим в начале задачи и не переключать его без причины.

Значение по умолчанию для новых сессий задаётся в `.env`:

```dotenv
CLAUDE_CODE_EFFORT_LEVEL=medium
```

Effort влияет на видимый текст, thinking, аргументы tool calls и количество вызовов инструментов. Это поведенческий сигнал, а не жёсткий лимит токенов.

### Отключение thinking

```dotenv
CLAUDE_CODE_DISABLE_THINKING=true
```

Это сильнее уменьшает output tokens, но может заметно ухудшить сложное планирование, поиск причин ошибки и многошаговые изменения. Оставляйте `false` по умолчанию и включайте только для простых, хорошо ограниченных задач.

### Prompt suggestions и progress summaries

Prompt suggestions и необязательные progress summaries выключены. Telegram уже показывает tool cards и потоковый ответ, поэтому дополнительная генерация не нужна.

### Краткие ответы

Встроенный skill просит Claude не описывать каждый вызов инструмента и не повторять постановку задачи. Итоговый ответ должен содержать результат, изменённые файлы, проверки и оставшиеся риски без полного diff и длинных логов. Это не обрезка готового сообщения: модель изначально генерирует меньше текста, поэтому такие токены не оплачиваются.

## Input tokens

### Точные инструменты

Для известных идентификаторов используются `rg` и `ast-grep`. `jq` фильтрует большие JSON-файлы и вывод команд, а Universal Ctags позволяет получить короткий индекс символов без чтения целых файлов.

### Semble

Semble включён по умолчанию:

```dotenv
SEMBLE_ENABLED=true
```

Он работает локально на CPU, индексирует код с учётом структуры и возвращает только релевантные chunks. Это полезно, когда нужный символ неизвестен и обычный grep привёл бы к множеству чтений. На первом использовании может потребоваться загрузка компактной retrieval-модели.

### Context7

Context7 выключен по умолчанию, потому что это внешний сервис:

```dotenv
CONTEXT7_ENABLED=false
```

Он полезен для узких, version-aware запросов к публичной документации библиотек и может заменить загрузку длинных страниц документации. Не передавайте туда исходный код или приватные данные. Для повышенных лимитов задайте `CONTEXT7_API_KEY` и добавьте имя переменной в `projects[].passEnv`, чтобы ключ был доступен только разрешённому проекту и попадал под redaction.

### Serena и Repomix

Serena остаётся opt-in для больших проектов. Repomix используется только с узким `--include`; полный репозиторий автоматически не загружается.

## Что исследовано, но не включено автоматически

LLMLingua показывает высокое сжатие длинных prompts в исследованиях, но требует отдельной модели-компрессора и может удалить синтаксически или логически важные части кода. Поэтому она не ставится прозрачным промежуточным слоем перед Claude. Для coding agent безопаснее сначала уменьшать контекст точным retrieval, а не сжимать уже выбранный исходный код токен за токеном.

Облачные semantic-grep сервисы также не включены по умолчанию: они требуют отдельного API-ключа и могут отправлять индекс исходного кода третьей стороне. Semble выбран как локальная альтернатива.

## Что не гарантируется

Нельзя обещать одинаковый процент экономии для каждой задачи. Слишком низкий effort или слишком узкий retrieval иногда приводит к дополнительным попыткам и в итоге тратит больше. Сравнивать режимы нужно на повторяемых задачах, учитывая итоговую стоимость и качество.

API-side `taskBudget` намеренно не включён по умолчанию. Это beta-возможность, которую кастомный Anthropic-совместимый gateway может не поддерживать.
